## EarthSciASTDiff v0.7.0

Every binding now requires EarthSciAST 0.15. The Julia and Rust bindings
differentiate operator references (`apply_operator`) without expanding
them. Each definition is differentiated once, and its result is combined
with the bindings of each use. Derived documents keep the source's
references and carry the definitions those references reach. This is a
breaking release: EarthSciAST 0.14 and older are no longer supported, the
emitted documents change shape, and the `cse` option no longer has an
effect.

### Breaking changes

- **EarthSciAST 0.15 is the floor in every binding** (Julia `0.15`, Rust
  `>=0.15, <0.16`, Python `>=0.15,<0.16`). Derived documents carry an
  `operators` block and `apply_operator` references. The flattened view
  relies on flatten keeping references, which no release before 0.15 does.
- **Derived documents keep operator references** (spec §3.6, §8.1). A
  coefficient that differentiates through a reference is written as a
  reference to a derived definition: `D.d_p` for a scalar definition, and
  `D.d_p.b<k>@<shape>` for a band of an array (stencil) definition at one
  binding shape. It is not written as the expanded body. Every evaluation
  and product document gets an `operators` block in each top-level model
  whose subtree holds a reference. That block holds the source definitions
  the references reach and the derived definitions. References are always
  written `apply_operator` / `operators`. A source that uses the earlier
  names `apply_expression_template` / `expression_templates` is read under
  the new ones. Points, structure and values equal those of the expansion.
- **`cse` and `cse_min_nodes` have no effect** (spec §4.1, §8.1). A
  `jacobians` block no longer carries block-local `expression_templates`,
  and the evaluation document is no longer hoisted (no `Jcse<n>` observed).
  The keywords are still accepted. Julia emits a deprecation warning for
  `cse = true`. Consumers still read a block that has templates.
- **Goldens regenerated** for the reference-keeping output: they keep
  references, have no block-local templates and no hoisting, and use the
  shape-named derived band definitions.

### New

- **Operator references are differentiated as references** (spec §3.6;
  Julia `operator_refs.jl`, Rust `operator_refs.rs`). This covers the
  chain rule through scalar definitions, and bands computed once per
  binding shape and composed at each use for array definitions. A model's
  own `operators` block is closed as flatten closes the merged registry:
  free names become trailing parameters. Second-order bands, recurrence
  self-bands and observed inlining all run under the reference layer.
- **A definition used at several binding shapes is supported.** Each
  shape gets its own derived definitions, named by shape so they never
  collide. A structural parameter, including one given as a range bound
  (`[1, "n"]`), is read as structural and specialized. New fixture
  `two_shape_stencil`.
- **Rust runs on EarthSciAST's real load and flatten.** Its flatten of
  `coupled_chem_advection` equals the recorded Julia flatten. The
  `tgrad_photolysis` time-band, block, evaluation, jvp and vjp goldens are
  compared again.

### Fixed

- A flattened registry body that read a name freely was differentiated only
  with respect to its parameters, and silently lost entries. It is now
  closed first. Rust refuses an open scalar body.
- Composition substitutes the inner band's index names everywhere in its
  coefficient. Before, an argument's band such as `2*u[_r1]` kept unbound
  index names.

### Known limitations

- **Python has no operator-reference layer yet.** Python EarthSciAST 0.15
  expands every reference at load (EarthSciAST#772). So the Python binding
  differentiates the expanded tree, and its documents hold expanded
  coefficients rather than references. The goldens that depend on kept
  references are skipped while the installed loader expands them. They run
  again once a Python release keeps references.

### Conformance

- conformance.yml now tests every binding at EarthSciAST 0.15.0, which is
  both the lowest and the latest release in range.
- Rust's clippy lint exempts `NodeRef` from `mutable_key_type`. EarthSciAST
  0.15's `ConstValue` caches its arrays internally, but a `NodeRef` hashes
  and compares by address, so the cache never affects a key.
