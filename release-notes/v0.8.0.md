## EarthSciASTDiff v0.8.0

Time-derivative bands keep the chain through time-dependent observed as
named steps. Before, every observed that moves with `t` was inlined into each
state row's right-hand side and differentiated there, so the same derivative
chain (photolysis rates, solar zenith angle, time-interpolation weights) was
written again in every row. On a full chemistry model this made the time
evaluation document about 69 MB, against 0.6 MB for the right-hand-side
document. Now each such observed's time derivative is written once, as its
own derived observed (its time companion), and every band reads it through
the chain rule. Nothing is inlined and then deduplicated.

### Breaking changes

- **Time bands read time companions** (spec §4.2). On a single `"time"`
  axis, an observed `o` that moves with `t` is no longer inlined. It is a
  column of the time pass beside `t`, and each band with column `o` is
  composed into a band with column `t` whose coefficient is
  `coef · _dt_o[φ]`. A band with contracted dimensions becomes a contraction
  sum in its coefficient, so every time band keeps its row's shape. Bands of
  one row with the same box are summed into one entry. The companion's own
  definition is built the same way from `o`'s definition: its direct
  derivative in `t` plus, for each time-dependent observed `o′` it reads,
  `∂def_o/∂o′ · _dt_o′`. Data stays held fixed: an observed that moves only
  with data-fed parameters gets no companion. The time coefficients,
  blocks, evaluation documents and `Jv` / `Jᵀλ` documents therefore change
  shape; their values do not.
- **Companion names and layout.** The companion of `o` is `_dt_<o>`
  (`P._dt_<v>` for a scoped `P.v`, in `o`'s component), with `_` appended
  until it is clear of every variable name, component path and index-set
  name of the source. A companion has `o`'s shape. An observed declared
  without a shape takes the extents its definition gives (an array-valued
  operator reference included), and one whose extents cannot be read so
  (array operands of different extents, a partial `index`) is refused, as
  are moving observed that read each other.
- **New block field `companions`** (spec §4). A `"time"` block whose
  coefficients read companions carries `[{name, of, rhs}]`, one per
  companion read directly or through another companion, in the order of the
  observed's name. The evaluation document (spec §8.1) and the time axis's
  product documents (spec §9.1) declare them as observed.
- **Time pairs take `t` second** (spec §4.4). A pair `["time", a2]` with no
  active recurrence is the time bands, by the companion rule, of each
  first-order `a2` entry's coefficient: with every branch frozen (§3.2) the
  mixed partials commute. Entries keep `col` `"t"` and take `col2` /
  `col2_idx` from the `a2` entry. An observed that moves only with `t` is
  reached through its companion rather than inlined into every row. The
  pair block carries `companions` and the `HvpEval` document declares
  them. `forcing_bracket.time-states.{bands,block,hvp.evaldoc}.json`
  change; its value golden does not.
- **Goldens regenerated** for the time axis: `tgrad_photolysis.time.*` and
  `tgrad_data_fixed.time.bands.json`. Their value goldens are unchanged, and
  every other golden is byte-identical.

### Unchanged

- A time pass, or a pair `["time", a2]`, through an active recurrence
  (spec §4.5) still follows the time-dependent observed by inlining: it
  composes the coefficients with a transfer.
- An observed that a column index reads is inlined on the time axis, as on
  every axis.

### Fixed

- An elementwise observed read at a cell whose definition reads a global
  named like the read's index (`index(jr, i, j)` with a parameter `j`) was
  refused on the time axis as a capture. The read is now a column and the
  companion row names its own indices, so it is differentiated.

### New

- **Fixture `tgrad_named_steps`** with time goldens (`bands`, `block`,
  `evaldoc`, `jvp` / `vjp` documents, `jvals`), checked byte for byte in
  Julia, Rust and Python. It has a scalar time-interpolation weight, an
  array blend of two temperature records by it, a rate of the blend, a
  state reading the rate at its own cell, a state reading it through a
  contraction over the vertical index, and data-fed parameters held fixed.
  Every binding checks its `f_t` against a central difference in `t` of the
  source right-hand side.
- **Time-pair goldens** for `["time", "parameters"]` and `["time",
  "forcing"]` on `forcing_bracket` and `tgrad_named_steps`, `["time",
  "states"]` on `tgrad_named_steps` and `tgrad_photolysis` (`bands`,
  `block`, `hvals`, `hvp.evaldoc`), checked byte for byte in Julia, Rust
  and Python and against ForwardDiff in Julia.
- `scripts/regenerate-value-goldens.jl` runs again: it builds the
  right-hand side as the test suite does (EarthSciAST removed the
  `build_evaluator` alias).
