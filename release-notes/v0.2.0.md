## EarthSciASTDiff v0.2.0

The Jacobian is now delivered as ESM documents that EarthSciAST evaluates,
and the bindings no longer evaluate anything themselves. Every product a
solver needs (`Jv`, `Jᵀλ` and the second-order contraction) is a derived
document that an unmodified EarthSciAST evaluator runs in one right-hand-side
call. The band calculus also covers more of the language: forcing buffers,
array parameters, second-order bands, filters, `max`/`min`/`*` reductions and
causal recurrences.

### Breaking changes

- **The evaluators are removed from all three packages.** Build the
  evaluation document (`evaluation_document`) or a product document
  (`jvp_document`, `vjp_document`, `hvp_document`) and evaluate it with
  EarthSciAST. Applying a scatter plan to the evaluated band fields is up to
  the consumer.
  - **Julia:** `prepare_jacobian` / `JacobianEvaluator` / `jac!`,
    `assemble_jacobian`, `jac_into!`, `vjp!`, `vjp_forcing!` and
    `prepare_hvp` / `HVPEvaluator` / `hvp!` are removed. The SciMLBase
    extension (`ode_components`, `odefunction`, `odeproblem`) is removed too.
  - **Rust:** `numeric.rs` and `program.rs` are removed: `assemble_jacobian`,
    `prepare_jacobian` / `JacobianEvaluator`, `vjp`, `vjp_forcing`,
    `band_fields`, `prepare_hvp` / `HvpEvaluator` / `hvp`, `JacobianProgram`
    and `HvpProgram`. `BoundScatter` is now plain data (`field_lens`,
    `pairs`), with no `scatter` method.
  - **Python:** `numeric.py` and its exports are removed.
- **Rust:** `SysView::variables` is now a `Cow<'a, IndexMap<…>>`.
  `.iter()`, `.get()`, `.keys()` and indexing work as before, but
  `for x in sv.variables` needs `.iter()`. `parse_jacobian_blocks` now returns
  `Vec<ParsedBlock>`, and `jacobian_blocks` takes `Into<BlockWrt>`, so
  existing `&[Wrt::…]` calls still compile.
- **Python 3.11 or newer is required** (was 3.9), because EarthSciAST 0.7
  requires it.
- **Supported EarthSciAST releases:**

  | Package | v0.1.0 | v0.2.0 |
  |---|---|---|
  | Julia | `0.4, 0.5, 0.6` | `0.6, 0.7` |
  | Rust | `0.6` | `>=0.5, <0.8` |
  | Python | unbounded | `>=0.4, <0.8` |

  EarthSciAST.jl 0.4 and 0.5 no longer precompile, so the Julia package now
  starts at 0.6. CI tests each package against both the oldest and the newest
  release in its range.
- **Array parameters are now columns on the `parameters` axis.** Before,
  their cells were silently dropped. On the `parameters` and `forcing` axes,
  a column outside its variable's extent, or one that isn't fixed at build
  time, is now an error.

### New

- **Product documents (spec §9)** in Julia, Rust and Python: `jvp_document`,
  `vjp_document` and `hvp_document` (`form = :contract` or `:symmetric`).
  Each returns the input and output names the caller fills and reads.
- **Scatter plans in Python** (`scatter_plan`, `serialize_scatter_plan`,
  `bind_plan`), matching Julia and Rust.
- **Forcing and array-parameter columns** (`wrt = "forcing"`, RFC U7). The
  forcing set is inferred from array parameters with a `data` update, or can
  be passed in.
- **Second-order bands** (spec §4.4, RFC U8): `"wrt": [a1, a2]` blocks for
  Rosenbrock discrete adjoints.
- **More operators** (RFC U9). Filtered `faq` nodes, `max`/`min`/`*`
  reductions and the `max_product` semiring, which used to be refused, are now
  differentiated. So are value-indexed reads, such as a level search
  `x[κ(u)]`. Index-only filters the band box can't express become an
  optional `where` on the entry. `column_block` structure and factorization
  plans are new too, including per-line `diag_plus_rank1`.
- **Causal recurrences** (spec §4.5), **Rust and Python only.** An observed
  that reads itself at an earlier cell is differentiated through a transfer
  recurrence, which is carried in the block's new `auxiliary` field. Product
  documents never form that recurrence explicitly. The Julia package doesn't
  differentiate recurrences yet; that waits on EarthSciAST.jl executing them.
- **Rust:** `sysview_flat` and `jacobian_bands_view` differentiate a
  flattened system; `plan_factorization` and `serialize_plan` are now
  exported.

### Fixes

- A unary `-` around a whole array expression lost its sign, in all three
  packages.
- A site whose subscripts contain a `faq` node no longer fails
  canonicalization.
