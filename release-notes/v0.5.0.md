## EarthSciASTDiff v0.5.0

Every binding now admits EarthSciAST 0.10. Subtree sharing in derived
documents and branch simplification are much faster on large operators. The
Julia `evaluation_document` can now take bands the caller has already
computed. This is a minor release. No public API changes, but two kinds of
output bytes change: the names of hoisted subtrees in some derived documents,
and the writing of `const` table values (see Conformance).

### New

- **Julia: `evaluation_document(input, entries; cse, cse_min_nodes,
  model_name, data_sources)`** builds the derived evaluation document from
  bands already computed with `jacobian_bands`, instead of computing them
  again. This matches the Rust `evaluation_document(sv, entries, cse,
  cse_min_nodes)`. `input` may be an `EsmFile`, a `FlattenedSystem` or the
  `SysView` the bands came from. Passing `data_sources` or `model_name`
  together with a `SysView` is an `ArgumentError`, and so is passing
  structure-only bands. The keyword-only form is unchanged. Under
  EarthSciIntegrator's planner, the evaluation document of ReSEACT's transport
  operator drops from 564 s to 114 s, and the document is byte-identical.

### Fixed

- **`stable_json` no longer depends on the EarthSciAST release.**
  EarthSciAST 0.10 writes a `const` node's `value` in canonical-number form
  (CONFORMANCE_SPEC §5.5.3.1 rule 1: `[0.5, 1.0, 2.0]` → `[0.5,1,2]`).
  Earlier releases wrote `1.0`, so the same document gave different goldens
  and structural keys (`skey`) depending on which EarthSciAST was installed.
  All three bindings now apply rule 1 to a `const` value themselves, at any
  depth (spec §5 item 2). An integral float anywhere else still keeps its
  `.0`.
- **Same-condition pruning in `simplify_branches`** (Julia and Rust). The
  census of conditions now includes a condition that `_assume` builds while
  pruning (`ifelse(q, x, y) < y` becomes `x < y` inside `q`'s true side).
  Before, an enclosing test of that new condition could skip a descent that
  still had something to prune. Python, which has no census, already pruned
  these cases. The goldens are unchanged.
- **Julia: only the new `evaluation_document` form accepts a `SysView`.**
  The other entry points (the keyword `evaluation_document`, the product
  documents, the scatter entry points, `jacobian_pattern`) accepted one by
  accident. They did so without documentation or tests, and
  `jacobian_pattern(sv)` computed every band before failing.

### Performance

- **Subtree sharing (`cse_templates`, `hoist_observed`) in one pass** (spec
  §4.1). The extraction used to re-index every expression for each subtree
  it extracted, so its cost grew roughly quadratically. On 40 of the 1668
  bands of ReSEACT's transport operator it took 319 s in Julia and 127 s in
  Rust. Each structurally distinct subtree is now indexed once and visited
  once, largest first, and the same subtrees are extracted as before. Spec
  §4.1 now states the rule, including the order of a node's child slots and
  the naming order, so all three bindings number hoisted subtrees the same
  way. The Julia and Python walks are now iterative.
- **Structural ids and hashes in branch simplification** (Rust). Rust's
  `simplify_branches` used to serialize whole subtrees to compare conditions.
  It now compares by structural hash and id, as the reference does, and keeps
  unchanged nodes instead of copying them. On ReSEACT's transport operator,
  `jacobian_bands` drops from 365 s to 89 s in Rust and from 438 s to 206 s in
  Julia. The band bytes are identical.
- Rust's band interner uses exact leaves (`1` is not `1.0`, `0.0` is not
  `-0.0`), so `x + 1` and `x + 1.0` are no longer merged before sharing is
  counted. Leaf keys in every binding now tell these apart, as the reference
  always has.

### Dependencies

- Every binding admits EarthSciAST 0.10: Julia `0.6, 0.7, 0.8, 0.9, 0.10`,
  Rust `>=0.5, <0.11`, Python `>=0.4,<0.11`. The floors are unchanged.

### Conformance

- Changed goldens:
  - Six derived documents rename some hoisted subtrees or templates, because
    of the numbering rule of spec §4.1. They hold the same subtrees.
  - The goldens of `recurrence_sweep` and `pbl_rank1`, which are written by
    the Rust binding, now write their `const` table values in
    canonical-number form (`[0.5,0.7,1,1.4,2,2.8]`). The values are
    unchanged.
